# Product Requirements Document (PRD) - Python Raw LGAP Daemon

> **개발 및 운영 워크플로우 (Development & Deployment Workflow)**
> - **코드 개발 및 수정**: 미니PC (Antigravity IDE 환경)에서 개발 후 GitHub로 Push
> - **실제 구동 및 현장 테스트**: 회사 노트북 (사내 보안 정책상 Antigravity 미사용)에서 GitHub Pull 후 Python venv 환경에서 실제 구동/테스트 수행

## 1. 개요 (Overview)
- **프로젝트명**: python-raw-lgap-daemon
- **목적**: 라즈베리파이/현장 장비와 실외기 간의 물리적 유선 연결(RS-485)을 통해, 외부 미들웨어(ESPHome, MQTT) 없이 파이썬 단독 데몬으로 LG 시스템 에어컨(LGAP 프로토콜)의 상태를 모니터링하고 제어하는 경량 PoC(개념 검증) 엔진 개발.
- **배경**: Wi-Fi 신호 불안정 및 이기종 게이트웨이 관리의 하드웨어 리스크를 제거하고, 산업용 장비의 안정성과 현장 설치 편의성을 극대화하기 위해 직접 RS-485 시리얼 통신 제어 구조로 피벗함.

## 2. 사용자 및 협업 환경 정의
- **개발 환경**: 
  - **코드 작업**: 미니PC (Windows, Python 3.10+, Antigravity IDE)
  - **실행 및 테스트**: 회사 노트북 (Windows/Linux, Python 3.10+ venv, 물리 RS-485 연결 장비)
- **물리 배선**: USB to RS-485 Isolated Converter를 사용하여 실외기 메인 PCB의 CENA/CENB 단자에 직접 유선 연결.
- **역할 분담**: 배선 설계, 전기 신호 무결성 확보 및 물리 디버깅은 하드웨어/장비 전문가가 담당. 소프트웨어 개발자는 오직 파이썬 내부의 시리얼 바이트 송수신 및 프로토콜 로직 무결성에 집중.

## 3. 핵심 기능 요구사항 (Functional Requirements)

### F-1. 물리 시리얼 포트 제어 및 안정화
- **설정 규격**: Baud rate 4800 bps, Data bits 8, Parity None, Stop bits 1 (8N1).
- **자동 복구**: 케이블 분리, USB 컨버터 재연결 등 물리적 단절 발생 시 `serial.SerialException`을 안전하게 캐치하고, 지수 백오프(Exponential Backoff) 알고리즘을 적용하여 자동으로 포트를 재오픈 및 복구해야 함.

### F-2. LGAP 프로토콜 패킷 핸들링 (XOR Checksum)
- **패킷 규격**: 16바이트 고정 크기 바이너리 패킷.
- **체크섬 룰**: 마지막 16번째 바이트를 제외한 앞 1~15바이트의 총합을 256으로 나눈 나머지(Modulo 256)를 구한 뒤, 이 값에 0x55를 XOR 연산한 최종 1바이트를 생성 및 검증.
- **프레이밍(Framing)**: RS-485의 라인 노이즈로 인해 깨진 바이트가 유입될 수 있으므로, 패킷의 시작을 알리는 헤더 바이트 패턴을 기준으로 16바이트 동기화를 정밀하게 맞춰야 함.

### F-3. 반이중(Half-Duplex) 순차적 폴링 엔진
- **동작**: 에어컨은 수동적(Passive) 장비이므로, 라즈베리파이가 주기적으로 상태 조회(Poll) 패킷을 보내고 응답을 기다려야 함.
- **스케줄링**: 실내기 ID별로 순차적으로 폴링을 수행(예: 3~5초 간격).
- **제어 명령 주입**: 사용자의 제어 명령(온도 변경 등)이 발생하면, 현재의 폴링 사이클을 안전하게 일시 정지(Preempt)하고 제어 패킷을 우선 전송한 뒤 응답을 확인하고 폴링 루프를 재개함.

### F-4. 경량 로컬 인터페이스 (PoC 최적화)
- PoC 단계이므로 별도의 복잡한 웹 UI나 외부 브로커 연동을 구현하지 않음.
- 설정값(대상 실내기 ID 리스트, 기본 온도 등)은 `config.py`에 하드코딩하여 사용 조작을 최소화함.
- 외부 제어 테스트용으로 Unix Domain Socket 또는 단순 로컬 UDP 포트를 열어두고, 제어 명령(JSON 포맷)을 수신하면 이를 데몬 내부의 Command Queue에 밀어 넣는 방식으로 설계.

## 4. 비기능 요구사항 (Non-Functional Requirements)
- **자원 효율성**: 가벼운 파이썬 단독 데몬으로 CPU 점유율 1% 미만 유지.
- **동시성 무결성**: 동일 시리얼 채널에 대한 다중 쓰기 방지를 위해 완벽한 동시성 락(Lock) 구현.
- **무중단 동작**: `systemd` 서비스 등록을 통해 프로세스 크래시 발생 시 OS 레벨에서 자동 리스타트 보장.
